# Plugin Eval Suite

End-to-end checks that run the skills through Claude Code and grade what they produce. Each case is a folder here (`prompt.md`, `case.yaml`, `setup.sh`, `graders/*.md`), and two runners read the same folders:

- **The harness** (`evals/harness/`) runs on Windows, macOS and Linux through a headless Claude Code session, and is the default:
  ```bash
  bin/construction-python evals/harness/run.py --tag smoke --runs 1
  ```
  See the [harness README](../harness/README.md) for requirements (on Windows, the native Claude Code install), options, and how runs are confined.
- **`claude plugin eval`** runs on macOS, Linux and WSL2 inside Claude Code's own sandbox, with its HTML report and with/without-plugin comparison:
  ```bash
  claude plugin eval . --tag smoke --scaffold --allow-tools Bash Write Edit
  ```
  `--scaffold` lets each case copy the sample project into its workspace and link the toolkit's Python environment; `--allow-tools Bash Write Edit` lets the skills run their scripts and write files; add `--runs 1 --ablation none` for a quick single pass. The sandbox needs `bubblewrap` and `socat` on Linux (`sudo apt install bubblewrap socat`) and is not available on native Windows. Results go to `evals/plugin/results/<timestamp>/`. The first run builds the toolkit's Python environment once in `.eval-home/` at the plugin root (about a minute, needs internet); eval runs themselves have no network.

Harness-only additions to a case (Python checks for xlsx and docx deliverables) live in `harness.yaml` and `checks/`, which `claude plugin eval` ignores.

## Tiers

### Smoke (`--tag smoke`) — included

A small synthetic project in `_fixtures/sample-project/`, generated by `_fixtures/make_fixtures.py`: a 4-sheet drawing set (A-201's bookmark is deliberately wrong) and a 2-section project manual. Through the harness on Sonnet, a single pass of the four cases takes about eight minutes and costs about $5 (from $0.55 for project-setup to $2 for submittal-log-generator).

| Case | Checks |
|---|---|
| `project-setup` | Context appended to `CLAUDE.md`; no AgentCM files created |
| `sheet-splitter` | Sheets split and named from the printed title block; index next to the sheets; nothing in `.construction/index/` |
| `spec-splitter` | Section PDFs produced; text in `.construction/skills/spec_text/` |
| `submittal-log-generator` | Runs spec-splitter itself; `Submittal_Log.xlsx` produced; items from both sections |

### Real documents (`--tag real`)

Cases built from the plans and specifications of Sanibel Fire and Rescue Station 172. The documents are too large for the repository, so they are downloaded separately and placed under `evals/test_docs/SANIBEL FIRE AND RESCUE STATION 172/` (see [Running Evals](../../docs/RUNNING_EVALS.md#get-test-documents)); `_fixtures/sanibel/make_fixtures.py` then derives small fixtures from them (single sheets, the 8-sheet mechanical set, two trimmed manuals, pre-split flooring sections). Without the downloads these cases are reported as skipped. The expected values come from `_fixtures/sanibel/derive_ground_truth.py`, which reads the same PDFs; its outputs are committed in `_fixtures/sanibel/ground_truth/`.

| Case | Inputs | Checks |
|---|---|---|
| `construction-guide` | Sheet A500 | Known-answer question on door 220: nine values with the sheet cited, the PDF rasterized rather than read directly, a confidence label |
| `schedule-extractor` | Sheet A500 | The door schedule to Excel: 53 doors, width, height, hardware set and material cell-by-cell against the transcription |
| `sheet-splitter-real` | The mechanical set | 8 sheets split and named from their title blocks; the index matches |
| `spec-splitter-real` | A 9-section manual | All sections split; text extracted for each; no POOR ratings |
| `submittal-log-real` | A 4-section manual | Runs spec-splitter itself; log rows cover the Part 1 submittal articles of 09 30 00, 09 65 13 and 09 65 40 |
| `tag-audit-and-takeoff` | Sheet A101 | Flat-file door tag audit: the 16 door numbers printed on the sheet, none invented, no AgentCM calls |
| `code-researcher` | G010, A101, Division 01 excerpts | Offline: facts read from the code summary (FBC 8th Edition 2023, B/R-2/S-2, Type V-B sprinklered), no COMPLIANT / NON-COMPLIANT verdicts, uncertainty stated |
| `pe-review` | Sheet A500 + synthetic Addendum 01 | Door 220: a CONFLICTING finding citing both sources, the addendum governing, severity/type/priority/status |
| `rfi-drafter` | A500, Addendum 01, the firm RFI template | Template mode (firm marker, no generic block), fields filled, facts right, issue registry record escalated |

### Synthetic documents (`--tag synthetic`)

The three skills that need bids or contracts run on generated fixtures in `_fixtures/synthetic/` (see `make_bids.py`, `make_templates.py` and `templates/README.md`): a five-bid flooring package against the real Division 09 sections with planted problems, a firm RFI template, and a 15-article subcontract template with a defective indemnity carve-out and stale example parties. No download needed.

| Case | Checks |
|---|---|
| `bid-tabulator` | Five bidders extracted; totals as stated (including the planted wrong one); alternates with sign; the buried exclusion, budget pricing and allowance captured; the smudged scan value flagged unclear; the scanned bid rasterized |
| `bid-evaluator` | From the tabulated JSON: the silent omission marked SILENT, the math error flagged not corrected, the buried exclusion scored, budget pricing not awardable, the clean low bid recommended, five workbook tabs |
| `subcontract-writer` | From the awarded bid and the template: parties and sum from the bid, `sole negligence` fixed and flagged, stale example parties dropped, no placeholders left, spec sections and bid exclusions carried in |

`viewport-highlighter` has no case: it needs a running AgentCM project.

Through the harness on Sonnet, one run of every case costs about $25-30; the real and synthetic cases range from under $1 (spec-splitter) to about $4 (code-researcher, tag-audit).

## Writing a case

Each case is a folder with `prompt.md` (frontmatter + the prompt), `case.yaml` (the scaffold), `setup.sh`, and `graders/*.md`. Copy an existing case. See the [plugin eval docs](https://code.claude.com/docs/en/plugin-evals) for grader types; the harness implements `file_exists`, `regex`, `tool_used`, `tool_order` and `llm`, plus `python` checks declared in `harness.yaml`.
