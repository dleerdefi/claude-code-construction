# Plugin Eval Suite

End-to-end checks that run the skills through Claude Code with `claude plugin eval` and grade what they produce.

## Run it

From the plugin directory (your clone, e.g. `~/.claude/skills/construction`):

```bash
claude plugin eval . --tag smoke --scaffold --allow-tools Bash Write Edit
```

- `--scaffold` lets each case copy the sample project into its workspace and link the toolkit's Python environment.
- `--allow-tools Bash Write Edit` lets the skills run their scripts and write files.
- Add `--runs 1 --ablation none` for a quick single pass. By default each case runs 3 times with the plugin and 3 times without it, to show how much the plugin adds.

Results and an HTML report go to `evals/plugin/results/<timestamp>/`.

**Platforms:** macOS and Linux. Claude Code runs eval agents in its sandbox, which needs `bubblewrap` and `socat` on Linux (`sudo apt install bubblewrap socat`) and isn't available on Windows. On Windows, run the suite in WSL or use the manual checks in [docs/VALIDATING.md](../../docs/VALIDATING.md).

**First run:** the scaffold builds the toolkit's Python environment once in `.eval-home/` at the plugin root (about a minute, needs internet). Eval runs themselves have no network.

## Tiers

### Smoke (`--tag smoke`) — included

A small synthetic project in `_fixtures/sample-project/`, generated by `_fixtures/make_fixtures.py`: a 4-sheet drawing set (A-201's bookmark is deliberately wrong) and a 2-section project manual. It takes about a minute and costs well under $1 per pass.

| Case | Checks |
|---|---|
| `project-setup` | Context appended to `CLAUDE.md`; no AgentCM files created |
| `sheet-splitter` | Sheets split and named from the printed title block; index next to the sheets; nothing in `.construction/index/` |
| `spec-splitter` | Section PDFs produced; text in `.construction/skills/spec_text/` |
| `submittal-log-generator` | Runs spec-splitter itself; `Submittal_Log.xlsx` produced; items from both sections |

### Real documents — in progress

Cases built from a real project's plans and specifications. The documents are too large for the repository, so they will be downloaded separately and placed under `evals/test_docs/` before running. These cases will be tagged `real`.

Planned coverage:

| Inputs | Skills |
|---|---|
| Plans + specs alone | project-setup, sheet-splitter, spec-splitter, submittal-log-generator, schedule-extractor (if the set has schedules), tag-audit-and-takeoff (flat-file mode), pe-review (graded against hand-picked real issues), rfi-drafter (generic format), code-researcher (reasoning only: eval runs have no web access) |
| Plus synthetic bids | bid-tabulator and bid-evaluator: several bids for one real spec section with alternates and unit prices: clean, unstated missing scope, heavy exclusions, math errors, wrong or missing alternates, scanned (image-only), different format (Excel or letter). Each planted problem is a ground-truth finding for bid-evaluator |
| Plus synthetic templates | subcontract-writer (awarded clean bid + firm subcontract .docx), rfi-drafter template mode (firm RFI .docx) |
| Needs AgentCM | viewport-highlighter (no standalone mode) |

construction-guide is exercised through the other cases.

## Writing a case

Each case is a folder with `prompt.md` (frontmatter + the prompt), `case.yaml` (the scaffold), `setup.sh`, and `graders/*.md`. Copy an existing case. See the [plugin eval docs](https://code.claude.com/docs/en/plugin-evals) for grader types.
